# 421. Maximum XOR of Two Numbers in an Array - LeetCode

## Problem Statement / Goal
Given an integer array `nums`, return the maximum result of `nums[i] XOR nums[j]`, where $0 \le i \le j < n$.

## Approach & Logic
The solution implements a **Trie (Prefix Tree)** of binary digits to find the maximum XOR efficiently:
1. Since the numbers are 32-bit integers, we can represent each number as a 32-bit binary path from the most significant bit (MSB) to the least significant bit (LSB).
2. Create a Trie with two branches: `0` and `1` at each node.
3. **Insert phase:** Insert the binary representation of every number from `nums` into the Trie.
4. **Search/XOR Phase:** For each number `nums[i]`, we try to traverse the Trie to maximize the XOR value. To maximize XOR, we want the bits of the XOR result to be as many `1`s as possible, starting from the MSB:
   - For a bit in `nums[i]`, we prefer to go down the opposite path (i.e. if the bit is `1`, we look for `0` in the Trie; if the bit is `0`, we look for `1`).
   - If the preferred child node exists, we follow it and set the corresponding bit in our temporary XOR sum to `1`.
   - If the preferred child does not exist, we are forced to take the other child (having the same bit), resulting in a XOR of `0` at that position.
5. Track the maximum XOR value found across all elements.

## Detailed Code Walkthrough
- `typedef struct Node`: Structure representing a node in the Trie. Contains an array `child[2]` for binary children (`0` and `1`).
- `Node* createNode()`: Helper function to allocate and initialize a new Trie node.
- `void insert(Node *root, int num)`:
  - Iterates from bit position 31 down to 0.
  - Extracts the bit at position `i` using `(num >> i) & 1`.
  - Creates a new node if the child branch for that bit is `NULL`.
  - Moves the current pointer to the child node.
- `int findMaximumXOR(int* nums, int numsSize)`:
  - Initializes the root of the Trie.
  - Inserts all elements in `nums` into the Trie.
  - For each element in `nums`, computes the maximum possible XOR value:
    - Traverses from MSB to LSB.
    - If the opposite bit branch (`1 - bit`) exists, takes it and sets that bit in the result (`value |= (1 << j)`).
    - Otherwise, takes the matching bit branch.
  - Updates the global maximum `ans` if `value > ans`.
  - Returns `ans`.

## Complexity Analysis
- **Time Complexity:** $O(N)$, where $N$ is the number of elements in `nums`. Specifically, we perform $32 \times N$ operations for insertion and $32 \times N$ operations for searching. This simplifies to $O(N)$ overall because the bit width is constant (32).
- **Space Complexity:** $O(N)$ to store the binary representations of up to $N$ numbers in the Trie. In the worst case, each number has unique bits, taking up to $32 \times N$ Trie nodes.
